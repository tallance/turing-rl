## Decision impact

- **Point 1 (generation decoding):** Paper **supports keeping our current choice unchanged** — our constants are byte-for-byte Table 4 (max 2048, top_p 1.0, top_k -1, presence 0.5, rep 1.0, temp 0.4/0.6). The observed repetition-loop degeneration and 2048-cap truncations are inherent to the paper's own published config, not a deviation on our part; any fix would be a deliberate departure from the paper.
- **Point 2 (packing):** Paper is **silent on packing/attention**, so it neither mandates nor forbids `--no_packing`; there is no methodology to "match" here. Keeping `--no_packing` is a safe implementation choice — it *upholds* the one thing the paper does state (completion-only loss with prompt/history masked, App. C.1), which trl `packing=True` under sdpa can violate via cross-conversation attention leakage. Recommend keeping it.

## Conflicts

No hard conflicts found. Every point either matches the paper exactly (1, 3, 4, 5, 7-core, 8) or concerns something the paper does not specify (2 packing; 6 judge decoding). The only soft divergences are additive, not contradictory: point 7's reward pipeline adds a 0.9 raw-reward scale, format bonuses, and per-response penalties on top of the paper's `(min{s,5}−1)/6` (the paper does include a length penalty). Minor note: `qwen3_8b_lora.yaml` does not itself set `max_seq_length` (code default 5120); the 8192 in Table 5 is supplied by the SFT launch scripts via `--max_seq_length 8192`.
